Self-hosted ML experiment tracking

Experiment tracking that holds up under audio and video load.

Resonance is a multi-tenant Weights & Biases replacement built to stay fast and correct when training runs log media at scale. Metrics, configs and per-step audio stream out of your training loop without ever blocking it, then you listen, scrub and A/B compare in the browser.

Why Resonance

Media is a typed, first-class artifact, not an opaque file.

Generic trackers bolt audio on as blobs: slow playback, no dedup, no precomputed views, storage bills that grow with every run. Resonance is built around the media path.

01 / SDK

Never blocks training

log and log_audio return immediately. Hashing, batching and upload run on a background thread, backed by a crash-safe local spool. Offline mode needs no network at all.

02 / Storage

Content-addressed and deduplicated

Every clip is keyed by its sha256. Existence is checked before upload, so a reference logged a thousand times is stored once.

03 / Upload

Bytes bypass the API

Clients upload straight to object storage with presigned URLs. A Go media gateway range-streams originals with HMAC-signed, CDN-cacheable links.

04 / UI

Audio-native views

Workers precompute waveform peaks and spectrograms, so the browser never decodes audio just to draw it. Scrub samples across training steps.

05 / Compare

A/B and blind tests

Synced A/B comparison and blind listening tests always play original-quality audio, never a lossy rendition. Ratings are logged.

06 / Tenancy

Hard multi-tenant isolation

Teams, hashed API tokens and RBAC, enforced twice: app-level scoping plus Postgres row-level security. Per-team storage quotas and tiering policies, plus rate limiting.

Architecture

Three data planes that scale independently.

Each kind of data lives in the store built for it, so a burst of media uploads can never slow down metric ingest or the control plane.

Event-driven derivation: new assets publish to Redpanda for fast processing, with a Postgres work queue as the correctness backstop. Derivation is idempotent across both paths.

Quickstart

One command up, three lines to log.

The dev stack runs every service locally with Docker. Point the SDK at it and log your first run.

terminal
git clone https://github.com/mishraprafful/resonance
cd resonance
make up
make demo
train.py
import resonance

run = resonance.init(project="vocoder", config={"lr": 3e-4})
for step in range(steps):
    run.log({"loss/mel": mel}, step=step)
    if step % 500 == 0:
        run.log_audio("samples/val", audio, sample_rate=22050,
                      step=step, reference=ref)
run.finish()
make upPostgres, ClickHouse, MinIO, Redpanda and Redis, plus ingest, API, media, workers and the UI on localhost:5280.
make demoLogs sample vocoder runs with full-length audio so the compare view has real material.
RESONANCE_MODE=onlineStreams to the running stack. The default offline mode spools runs to ./.resonance instead.
